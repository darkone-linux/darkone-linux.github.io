Passerelle (créer une zone)

Une zone est un sous-réseau, qui comporte une passerelle, derrière laquelle on branche autant de machines qu’on veut. La première passerelle s’installe depuis le poste d’administration, posé à côté d’elle, sans serveur de coordination.

darkone add gateway fait tout depuis le poste d’administration : appairage de la machine, déclaration dans etc/config.yaml, installation, recâblage, contrôles. La variante manuelle reste possible.

Le matériel

Section intitulée « Le matériel »

La passerelle est idéalement installée sur un mini-ordinateur toujours allumé, avec au moins deux interfaces réseau : une vers la box (WAN), les autres vers le réseau local (LAN, ethernet ou wifi).

Quel matériel ?

Par exemple, boîtier Protectli 🡕 ou équivalent :

  • Disque NVMe ≥ 256 Go
  • BIOS coreboot de préférence
  • Carte wifi en option

Câblage

Section intitulée « Câblage »

Le WAN de la passerelle va sur la box ; tout le réseau local passe derrière elle.

  • Le Wi-Fi de la box reste hors de la zone : ses appareils ne reçoivent pas d’adresse de la passerelle.
  • Un point d’accès Wi-Fi se branche derrière la passerelle, sans DHCP.
  • Le commutateur est facultatif : un poste peut se brancher sur un port LAN.

Installer avec l’assistant

Section intitulée « Installer avec l’assistant »

darkone add gateway se lance sur le poste d’administration, dans le projet (/etc/nixos). Il ne demande que l’adresse de la machine et son code.

Version du générateur

darkone add arrive avec une release du générateur postérieure à la v0.4.0. Avec une version plus ancienne, la commande n’existe pas : variante manuelle.

  1. Brancher

    Le WAN de la passerelle sur la box. Le poste d’administration reste sur la box (câble ou Wi-Fi).

  2. Démarrer

    Sur l’ISO générique, gravée sur une clé USB, entrée 2) Add this machine to an existing network du menu (ou dnf-pair). L’écran donne l’adresse et le code d’appairage :

  3. Lancer

    L’assistant demande l’adresse, puis le code. Il sonde la machine et propose le nom (gw), le WAN (la carte qui porte la route vers la box), le LAN (les autres cartes filaires) et le disque (une question s’il y en a plusieurs).

  4. Confirmer

    Le récapitulatif nomme le disque effacé et les choix définitifs. Vient ensuite le diff de etc/config.yaml, avec une seconde confirmation : rien n’est écrit avant.

  5. Recâbler

    À l’invite Now unplug this machine from the box and plug it into a LAN port of gw, brancher le poste d’administration sur un port LAN de la passerelle. L’assistant reprend seul, applique ce poste (just apply-local) et contrôle le réseau.

Le message final, Step 2 of 4 done, annonce l’étape 3.

À valider

L’enchaînement complet est testé de bout en bout en machines virtuelles (box simulée, passerelle à deux cartes), pas encore sur du matériel.

Le code d’appairage

Section intitulée « Le code d’appairage »

Le code PPPPPP-FFFF prouve que l’adresse tapée est la bonne machine avant l’envoi de la moindre clé.

PartieRôle
PPPPPPmot de passe nixos, à usage unique, valable 10 min
FFFFempreinte de la clé d’hôte, vérifiée par le poste

Le poste calcule FFFF depuis la clé qu’il lit sur le réseau : si elle diffère, rien n’est envoyé. Sinon il pousse sa clé de déploiement (usr/secrets/nix.pub) et verrouille le mot de passe ; l’écran affiche Paired. La clé d’hôte vérifiée est ensuite tenue jusqu’à la fin de l’installation. Une machine déjà appairée ne redemande pas de code.

Plan à blanc, réponses

Section intitulée « Plan à blanc, réponses »

--dry-run appaire et sonde la machine, puis affiche le plan, le diff de etc/config.yaml et les commandes d’une vraie exécution. Rien n’est écrit dans le projet ; la machine, elle, reste appairée.

Un fichier de réponses remplace les questions. Le code d’appairage n’y entre jamais : il se tape sur le terminal.

  • confirm: true saute les deux confirmations (le diff reste affiché) ; sans lui, --non-interactive refuse de commencer.
  • Une clé inconnue est refusée ; toutes les erreurs sont listées d’un coup.

Refus

Section intitulée « Refus »

L’assistant refuse avant d’écrire quand :

CasÀ faire
Dépôt non proprecommiter ou remiser
Passerelle déjà là, ou plusieurs zonesdéclarer à la main
Réseau de la box dans la zonechanger le réseau de la box
Moins de deux cartes filairesprendre une machine à deux cartes
Machine en BIOSpasser le firmware en UEFI

Le préfixe de la zone est définitif : si la box le recouvre, c’est elle qui bouge. La disposition server-1-disk exige l’UEFI. Les disques de moins de 20 Go (clé USB) ne sont pas proposés.

Écrit dans le projet

Section intitulée « Écrit dans le projet »

Après confirmation, l’assistant écrit dans etc/config.yaml le bloc gateway de la zone et l’hôte gw (<zone>:1.1). Le poste d’administration reçoit son adresse fixe (<zone>:2.1) et sa mac si elles manquent. Puis just clean et le commit chore(gateway): add gw.

Reprise après échec

Section intitulée « Reprise après échec »

Le message d’échec liste les commandes restantes, dans l’ordre.

ÉchecÉtatReprise
Avant l’écriturerien de changérelancer
just clean, commitfichier écrit, rien de commitésuite à la main, ou git stash --include-untracked puis relancer
just full-installdéclaration commitéejust full-install gw nixos <ip>, puis just apply-local
just apply-localpasserelle installéejust apply-local
Contrôlespasserelle installéele remède suit chaque contrôle

Une fois la déclaration commitée, darkone add gateway refuse de rejouer (la zone a sa passerelle) : la reprise est à la main, et repose la question de formatage. Les contrôles vérifient la route par défaut (la passerelle), la résolution de gw et l’accès à Internet.

Variante manuelle

Section intitulée « Variante manuelle »

Sans l’assistant, la même installation se fait recette par recette : la déclaration dans etc/config.yaml précède just full-install.

Préparer la passerelle

Section intitulée « Préparer la passerelle »

  1. Brancher

    Le WAN de la passerelle sur la box. Le poste d’administration reste sur la box (câble ou Wi-Fi).

  2. Démarrer

    Sur l’ISO, gravée sur une clé USB. L’écran donne ce qu’il faut déclarer :

    LigneSert à
    - IP:just full-install
    Network cardswan.interface, lan.interfaces
    Disksdisko.devices (chemin à copier)

    La carte marquée default route (WAN) porte la route vers la box : c’est le WAN, les autres câblées sont le LAN. dnf-netinfo réaffiche l’écran. Avec l’ISO générique, l’entrée du menu 2) Add this machine to an existing network affiche les mêmes tableaux.

    L’écran affiche aussi le code d’appairage (Pairing code: PPPPPP-FFFF) : just full-install le demande à l’étape 4, rien à autoriser avant. L’image just build-iso porte déjà la clé : pas de code.

Déclarer la zone

Section intitulée « Déclarer la zone »

Tout se déclare avant l’installation : la passerelle naît avec la réservation du poste d’administration, qui reçoit son adresse fixe dès le recâblage.

  1. Déclarer

    Dans etc/config.yaml : le bloc gateway de la zone, l’hôte gw, et une adresse fixe pour le poste d’administration.

    Pas de mac pour la passerelle : son adresse LAN est fixe (1.1) et son adresse WAN vient de la box.

Services et liaisons de secours

Le profil gateway câble le routeur, le pare-feu, le DNS/DHCP (dnsmasq) et le client VPN (voir Réseau). Les services (adguardhome, homepage…) se déclarent sous services:. Un port libre ou une carte wifi peut servir de liaison de secours.

Installer la passerelle

Section intitulée « Installer la passerelle »

  1. Installer

    • gw : nom d’hôte déclaré.
    • nixos : utilisateur de l’ISO.
    • 192.168.1.50 : la ligne - IP: de l’écran.

    Avant la question de formatage, la recette annonce le recâblage : get the cable ready now. Le disque est ensuite formaté, le système installé, puis la passerelle redémarre.

    Si le réseau de la box chevauche celui de la zone (la box dans 10.0.0.0/16), la recette refuse avant tout formatage : WAN et LAN seraient sur le même réseau.

    Le préfixe de la zone est définitif : changer le réseau de la box (sous-réseau ou plage DHCP), redémarrer l’ISO, recommencer.

  2. Recâbler

    À l’invite Now unplug this machine from the box and plug it into a LAN port of gw, débrancher le poste d’administration de la box et le brancher sur un port LAN de la passerelle (ou du commutateur). Rien à presser : la recette attend jusqu’à 30 minutes que 10.0.1.1 réponde, puis enchaîne configure, apply et un dernier redémarrage.

    Sans réponse après 30 minutes :

    Cette pause n’a lieu que si la passerelle garde son SSH fermé côté box (coordination inactive, ou gateway.vpn.ipv4 déjà déclaré) : voir Accès SSH selon le rôle.

  3. Finir

    Le poste d’administration prend son adresse fixe (10.0.2.1).

À valider

Essayée en machines virtuelles, poste câblé : le poste prend un bail de la passerelle dès le recâblage, et gw se résout. Reste à confirmer sur une vraie installation : poste sur le Wi-Fi de la box et câblé au LAN, 10.0.1.1 répond sans rien débrancher.

Chiffrement du disque

Section intitulée « Chiffrement du disque »

Pour une première passerelle, préférer un disque en clair (server-1-disk) : elle redémarre seule après une coupure de courant, sans quoi le réseau reste coupé tant que personne ne tape la passphrase. Le chiffrement et le déverrouillage à distance sont décrits dans Chiffrement des disques (LUKS).

À valider : passerelle chiffrée

Le déverrouillage se ferait côté box avant le recâblage, puis côté LAN au dernier redémarrage. En câble direct, le poste peut perdre son adresse pendant l’initrd (pas de DHCP) : sinon, passphrase à la console.

Installer depuis une autre zone

Section intitulée « Installer depuis une autre zone »

Une passerelle se prépare souvent ailleurs que chez son destinataire. Branchez son interface WAN au réseau local de la zone d’accueil : elle y reçoit l’adresse de passage que cette zone lui réserve sur sa MAC. Ici, la clé mac de la passerelle (ligne - MAC: de l’écran de l’ISO) reste utile.

Trois conditions :

  • la clé mac de la passerelle est déclarée dans etc/config.yaml ;
  • la passerelle de la zone d’accueil a été redéployée depuis cette déclaration ;
  • la machine d’administration aussi, pour que SSH lise la redirection posée pendant l’installation.

Ensuite, just full-install gw se passe d’adresse : l’outillage calcule la cible et la suit d’un bout à l’autre. Le principe est décrit dans Machines hors de leur zone.

Une fois la passerelle livrée

Sur place, elle reprend l’adresse fixe de sa zone (.1.1). La redirection SSH posée pour l’installation ne sert plus : just roaming-clear gw.

Installer à distance

Section intitulée « Installer à distance »

Une personne sur place branche la passerelle à la box et la démarre sur l’image just build-iso (elle porte la clé de déploiement) ; l’administrateur installe par SSH. Cette voie suppose la coordination (HCS) active et gateway.vpn.ipv4 non déclaré : sinon le SSH reste fermé côté box une fois la passerelle installée.

  1. Rediriger le port 22 de la box vers la passerelle.
  2. Installer avec l’adresse IP publique de la box : just full-install gw nixos <ip-publique>.
  3. Retirer la redirection après avoir déclaré gateway.vpn.ipv4 et appliqué : la passerelle ne répond plus depuis Internet, l’accès passe par le VPN (just enter gw).

Enregistrer la passerelle sur le VPN

Section intitulée « Enregistrer la passerelle sur le VPN »

Une passerelle est un client Tailscale : elle publie le sous-réseau de sa zone dans le tailnet. Tant qu’elle n’y est pas enrôlée, les autres zones ne la voient pas. just full-install l’enrôle au passage ; sinon, ou pour vérifier :

Reste à déclarer son adresse tailnet : voir Enregistrer une passerelle.

Brancher d’autres machines

Section intitulée « Brancher d’autres machines »
  • Postes Linux : voir Ajouter une machine.
  • Smartphones, tablettes, PC tiers : se connectent automatiquement au réseau de la passerelle.

Remplacer le matériel

Section intitulée « Remplacer le matériel »

Changer l’ordinateur d’une passerelle en service relève d’une procédure distincte : la machine est neuve, mais son état ne l’est pas. Voir Migrer le matériel d’une passerelle.

FAQ

Section intitulée « FAQ »

Une faute de frappe sur le code ?

Section intitulée « Une faute de frappe sur le code ? »

Un code faux coûte 10 secondes d’attente (délai PAM), et l’assistant accepte trois essais. Un code faux et un code expiré donnent le même refus : relire l’écran. Après six codes de 10 minutes, l’appairage se ferme ; la commande dnf-pair de la machine en tire un nouveau.

« not the machine whose screen shows this code » ?

Section intitulée « « not the machine whose screen shows this code » ? »

L’empreinte FFFF du code ne correspond pas à la machine qui répond à cette adresse : autre appareil du réseau, adresse mal relevée. Rien n’a été envoyé ; vérifier l’adresse sur l’écran.
