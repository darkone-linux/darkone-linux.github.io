darkone.service.openclaw

Assistant OpenClaw d’un espace IA (passerelle + interface de contrôle, derrière le SSO de la zone).

Une instance par hôte ai-space, déclarée comme tout service :

  • accès : Caddy forward auth, membres de space-<host> uniquement (proxy.spaceMembersOnly) ; OpenClaw fait confiance à la passerelle de zone comme proxy (trusted-proxy) et lit l’identité dans x-auth-request-email ;
  • tailnet : l’appareil personnel d’un membre passe sans le SSO (proxy.tailnetIdentity), seul accès pour l’application Android ;
  • appareils : le navigateur d’un membre est appairé à la première visite, sans administration par l’opérateur (accordée seulement depuis la CLI de l’hôte) ; l’application avec openclaw qr ;
  • port : accessible depuis la passerelle de zone uniquement ;
  • CLI de l’hôte : openclaw (seul : la TUI), relancée sous l’utilisateur du service, après trusted-proxy avec le mot de passe de la passerelle (openclaw-gateway-password, just space-init) ; administrateurs et cliUsers (par défaut : le propriétaire) uniquement ;
  • état : /var/lib/openclaw (connexions aux fournisseurs, sessions, espace de travail, clés E2EE Matrix) ;
  • propriétaire (owner, par défaut : le seul membre) : son abonnement fait tourner l’agent, il reçoit les demandes d’approbation et les messages proactifs ;
  • Matrix : canal en messages privés avec le bot @<host>:<domain>, membres uniquement, salons ignorés, une session par membre s’ils sont plusieurs, lorsque le réseau dispose de Matrix et que just space-init <host> a créé le bot (marqueur var/generated/spaces/<host>.nix, jeton dans le fichier sops de l’espace) ; approbations d’exécution demandées au propriétaire en messages privés ;
  • outils de l’agent : MCP, skills, Claude Code / Codex / OpenCode et packages de l’espace (darkone.host.ai-space), partagés avec les répertoires personnels des membres ;
  • identité (identity : nom, emoji, avatar) : imposée, y compris sur le bot Matrix (nom affiché ; avatar, sinon l’emoji dessiné), l’avatar étant envoyé par just space-init <host> (avertissement à l’évaluation si obsolète) ;
  • mutableConfig : configuration modifiable depuis l’interface et la CLI, clés Nix fusionnées à chaque démarrage (imposées : accès, canaux, plugins, identité, chemins du store ; amorcées une seule fois : modèle, exec, talk…), le propriétaire reçoit operator.admin ;
  • espace de travail (/var/lib/openclaw/workspace) : fichiers workspace (AGENTS.md, SOUL.md…) remplacés à chaque démarrage, les autres laissés à l’agent ;
  • projets : le projectsDir partagé de l’espace sert de répertoire de travail à l’agent (agents.defaults.cwd), les projects y sont clonés avec git une seule fois ;
  • agents de code (Claude Code, Codex, OpenCode de l’espace) : workers en arrière-plan (skill coding-agent), sessions liées au chat (/acp spawn, acpx) ;
  • Talk (talk) : conversation vocale en direct (navigateur, application Android), GPT-Live d’OpenAI (connexion ChatGPT d’abord) ou Gemini Live (GEMINI_API_KEY), travail délégué à l’agent (agent-consult) ;
  • workflows : pipelines Lobster (lobster, fichiers .lobster via workspace), automatisations déclarées (automations, synchronisées, les autres laissées à l’agent et à l’interface) ;
  • notes vocales : whisper.cpp (transcription) ; sur un invité microVM, le serveur de l’hyperviseur (large-v3-turbo), ggml small local en secours ; local uniquement sur matériel nu.

Commandes exécutées sans approbation par défaut

exec = "full" (par défaut d’OpenClaw) : l’agent exécute toute commande sous openclaw, les jetons de l’espace à portée de main. La microVM est la frontière, l’unité durcie un second mur (écritures dans l’état seulement). ask, auto : les cas non couverts vont au propriétaire, un garde-fou contre les erreurs, pas un mur (même utilisateur).

Les membres se font confiance

Une passerelle, un seul domaine d’opérateur : l’interface de chaque membre affiche toutes les sessions, messages privés compris. Les membres qui ne se font pas confiance disposent d’espaces séparés.

Modèles : model + extraModels (/model dans le chat), les subscriptions du propriétaire d’abord, sinon une clé API (apiKeys, sops openclaw/<VAR>) ; providers ajoute des points d’accès compatibles OpenAI (Nous Portal…).

Connexion aux fournisseurs

Une fois par espace, depuis l’hôte en tant que nix (la CLI openclaw se relance elle-même sous l’utilisateur du service, aussi pour cliUsers), par abonnement. Les connexions restent dans l’état.

  • anthropic : sudo -u openclaw -H claude auth login ;
  • openai : openclaw models auth login --provider openai.

Options

Section intitulée « Options »

  • enable bool Active l’assistant OpenClaw d’un espace IA

  • owner nullOr str Membre propriétaire de l’espace : son abonnement connecte l’agent (model), il reçoit les demandes d’approbation et les messages proactifs. Obligatoire avec plusieurs membres (l’ordre de users n’est pas conservé).

  • cliUsers listOf str Membres lançant la CLI de l’hôte (openclaw) sous l’utilisateur du service, par une règle sudo : TUI, connexions aux fournisseurs, administration. Leurs commandes shell ! s’exécutent aussi sous openclaw, les jetons de l’espace à portée de main.

  • model str Modèle principal, <provider>/<model> : via l’abonnement du propriétaire lorsque son fournisseur figure dans subscriptions, sinon une clé API (apiKeys).

  • extraModels listOf str Autres modèles du catalogue, choisis dans le chat avec /model ; mêmes règles que model.

  • subscriptions listOf ( enum [ "anthropic" "openai" ] ) Abonnements du propriétaire, utilisés en premier par les modèles de leur fournisseur :

    • anthropic : Claude Pro/Max via la CLI claude (nécessite darkone.host.ai-space.enableClaude) ;
    • openai : ChatGPT Plus/Pro via le plugin codex.

    Les autres fournisseurs, ou ceux absents, passent par une clé API (apiKeys).

  • apiKeys listOf (strMatching "[A-Z][A-Z0-9_]*") Clés API des fournisseurs, par variable : lues dans le fichier sops de l’espace (openclaw/<VAR>, just space-sops <host>) vers l’environnement de la passerelle. ANTHROPIC_API_KEY est écartée à côté de l’abonnement anthropic, qu’elle remplacerait.

  • providers attrs Fournisseurs absents d’OpenClaw (Nous Portal…), compatibles OpenAI par défaut.

    • baseUrl str Point d’accès de l’API.
    • api str Variante de l’API (models.providers.<id>.api d’OpenClaw).
    • apiKey nullOr (strMatching "[A-Z][A-Z0-9_]*") Variable de la clé, lue comme apiKeys.
    • models listOf str Identifiants de modèles, référencés comme <provider>/<id>.

  • mutableConfig bool Configuration modifiable depuis l’interface et openclaw config set, le propriétaire étant administrateur opérateur. Clés Nix fusionnées à chaque démarrage :

    • imposées, réécrites (aussi à tout changement du fichier) : passerelle et accès, canal Matrix, plugins, serveurs MCP, identity, chemins du store ;
    • amorcées, écrites si absentes, puis les règles de l’interface : model, exec, talk, ACP, interrupteurs des skills.

  • exec enum [ "full" "auto" "ask" "allowlist" "deny" ] Politique de commandes de l’agent (tools.exec.mode d’OpenClaw) :

    • full : toute commande, sans approbation (défaut d’OpenClaw) ;
    • ask : les commandes de la liste blanche s’exécutent, les autres demandent au propriétaire ;
    • auto : un modèle examine les cas non couverts, le propriétaire décide en cas de doute ;
    • allowlist, deny : commandes de la liste blanche seulement, aucune.

    Liste blanche : openclaw approvals allowlist add --agent main <path>. Avec le runtime claude-cli, les tubes, redirections et substitutions sont refusés avant toute demande, hors full.

  • identity.name nullOr str Nom de l’assistant, dans l’interface et sur le bot Matrix (par défaut ici : le name de l’hôte).

  • identity.emoji nullOr str Emoji de l’assistant, dans l’interface ; dessiné comme avatar du bot Matrix sans avatar.

  • identity.avatar nullOr (either str path) Avatar de l’assistant :

    • fichier (png, jpg, gif, webp ; 2 Mo au maximum pour l’interface) ou URL https:// : interface et bot Matrix, envoyé par just space-init <host> ;
    • chemin relatif à l’espace de travail : interface seulement, l’emoji sur Matrix.

  • matrixProfile raw Profil du bot Matrix : nom affiché, avatar et son empreinte.

  • workspace attrs Fichiers de l’espace de travail de l’agent, par chemin relatif : contenu ou fichier. Remplacés à chaque démarrage de la passerelle ; les fichiers non déclarés appartiennent à l’agent.

  • projects attrs Dépôts git clonés une seule fois dans <projectsDir>/<name> (darkone.host.ai-space.projectsDir), jamais mis à jour. Les dépôts distants SSH utilisent la clé de openclaw (/var/lib/openclaw/.ssh, créée à la main) ; la clé du serveur est acceptée au premier clone.

  • talk.enable bool Talk : conversation vocale en direct (navigateur, application Android)

  • talk.provider enum [ "openai" "google" ] Voix en temps réel :

    • openai : GPT-Live, WebRTC dans le navigateur, SDP via la passerelle ;
    • google : Gemini Live, audio relayé par la passerelle, nécessite GEMINI_API_KEY dans apiKeys (clé Google AI Studio).

  • talk.model str Modèle temps réel, par fournisseur :

    • openai : gpt-live-1-codex via la connexion ChatGPT du propriétaire (openclaw models auth login --provider openai), sinon une clé Platform (OPENAI_API_KEY) ; gpt-live-1, gpt-realtime-2.1 (caméra) : clé Platform uniquement. Épinglé : non défini, une clé Platform l’emporte sur ChatGPT ;
    • google : gemini-3.1-flash-live-preview, gemini-3.8-live.

  • talk.voice str Voix de la route du modèle :

    • gpt-live-1-codex : cove, arbor, breeze, ember, juniper, maple, sol, spruce, vale ;
    • Gemini Live : Kore, Puck, Charon, Aoede, Zephyr… (30 voix prédéfinies, listées dans Settings → Talk).

  • talk.instructions nullOr lines Instructions ajoutées au prompt temps réel d’OpenClaw.

  • lobster bool Workflows Lobster : pipelines exécutés par la passerelle, avec étapes d’approbation et reprise, plus llm-task (étape LLM structurée). Les fichiers de workflow passent par workspace ("workflows/<name>.lobster").

  • automations attrs Exécutions planifiées de l’agent déclarées en Nix, synchronisées à chaque démarrage (nix-<name>, modifications faites dans l’interface écrasées) ; celles de l’agent et de l’interface sont laissées intactes.

    • schedule str Expression cron (5 ou 6 champs), ou every <durée> (every 2h).
    • message lines Prompt de l’exécution de l’agent.
    • announce bool Envoyer la réponse finale dans le chat (dernier canal du propriétaire).
    • model nullOr str Modèle remplaçant, <provider>/<model> ou alias.
    • enable bool Faux : reste désactivée ; une fois dans cet état, réactivée depuis l’interface seulement (openclaw automations enable <id>).

  • transcription.enable bool Transcrire les notes vocales (whisper.cpp, CPU).

  • transcription.backend enum [ "hypervisor" "local" ] Où les notes vocales sont transcrites :

    • hypervisor : le serveur whisper.cpp de l’hyperviseur (modèle plus grand, plus de cœurs), model en secours ;
    • local : sur cet hôte, avec model.

  • transcription.model path Modèle ggml de whisper.cpp pour la transcription locale (backend local, secours).

  • transcription.language str Langue parlée (auto : détectée pour chaque note).
